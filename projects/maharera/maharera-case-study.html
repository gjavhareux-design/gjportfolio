The challenge

Two products, two challenges.

Hard to understand, hard to complete

The website confused homebuyers, while the portal frustrated applicants. We tackled the website first, because it serves the most people.

Website

  • Poor Navigation & Discoverability: Project search required exact registration numbers, making it unusable for a first-time buyer.
  • Cognitive Overload: Data was presented as raw PDFs and dense tables with zero visual hierarchy.
  • Lack of Transparency: No way to see a project's real-time status (e.g., on-track, delayed, or under complaint) at a glance.
  • Accessibility Failure: Ignored GIGW and WCAG guidelines mandated for government sites.
Problem statement

Homebuyers find the website difficult to use due to its complex structure and convoluted design.

Not part of this case study

Application Portal

  • Data Loss & Rework: Multi-step registration lost data upon session timeout, forcing promoters to redo hours of work.
  • Lack of Visibility: No visible status tracker for applications under review, leading to repeated calls to MahaRERA staff.
  • Late-Stage Rejections: Document upload rules weren't validated until final submission, causing avoidable delays.
  • Confused User Journeys: Promoter and agent workflows were merged into a confusing, non-role-based form set.
Problem statement

Users struggle to complete applications due to broken workflows, dropped sessions, long forms, and endless document uploads.

As-is journey map · Homebuyer

From curious to confused.

A homebuyer's journey on the old MahaRERA website

The old MahaRERA website journey reveals several usability challenges as users navigate from discovering the platform to making an informed property purchase decision. Users experience difficulty locating projects, navigating complex search options, understanding regulatory information and comparing project details across multiple sections. These challenges create frustration, uncertainty and reduced trust in the information presented. The journey highlights key opportunities to simplify navigation, improve information accessibility and create a more transparent, intuitive user experience.

UX Pain Points

Key issues that made the MahaRERA website hard to use

01

User tasks are buried

Users struggle to find key actions like finding a project, checking a developer, or filing a complaint.

02

No central search

Finding projects, developers, RERA IDs or locations takes extra effort.

03

Too much information

Dense legal and informational text makes the page difficult to read. Important information is buried instead of being easy to scan.

04

Confusing navigation

Menu labels are unclear, navigation is crowded and hard to use, and important tools are spread across different areas of the website.

05

Outdated and inaccessible interactions

Moving banners and auto-scrolling content can be distracting. The 3D chart is hard to interpret and the layout doesn’t work well across all devices.

    Three lessons from designing for a regulator

    01

    Design for the least expert user

    If a first-time buyer can do it, everyone else can do it faster.

    02

    Map assumptions early

    Testing the riskiest guesses first saved weeks of rework.

    03

    Saying no is design

    The discarded ring kept the site focused on what a regulator should do.
